2. Câu chuyện 8 bước: Khi bạn gõ ssh user@server

01Bắt tay kết nối

Client gửi yêu cầu tới cổng 22. Trên server, tiến trình sshd (SSH Daemon) đang lắng nghe 24/7 nhận cuộc gọi và mở /etc/ssh/sshd_config để biết được cấu hình: có cho phép root login? Dùng key hay password? Bật PAM?

02Hiện banner cảnh báo

Nếu sshd_config có dòng Banner /etc/issue.net, server in file /etc/issue.net trước khi bạn nhập gì cả. Thường là cảnh báo pháp lý.

03Xác thực (Authentication)

Server hỏi "bạn là ai?". sshd giao việc cho PAM qua /etc/pam.d/sshd:

  • pam_unix.so đọc /etc/passwd + /etc/shadow để check password. Nếu dùng SSH key thì sshd đối chiếu ~/.ssh/authorized_keys.
  • pam_env.so đọc /etc/environment nạp biến môi trường (LANG, PATH cơ bản).

04Kiểm tra tài khoản (Account)

PAM hỏi tiếp: "tài khoản này có được phép login lúc này không?":

  • pam_nologin.so check /etc/nologin — nếu tồn tại (admin tạo lúc bảo trì), user thường bị chặn, chỉ root vào được.
  • Module khác: check account hết hạn, giờ được login, IP có bị block.

05Chuẩn bị session

Chuẩn bị "không gian làm việc":

  • pam_limits.so đọc /etc/security/limits.conf áp giới hạn tài nguyên (số file mở, process, RAM).
  • pam_lastlog.so in "Last login: ..." và ghi vào /var/log/lastlog.
  • pam_motd.so in MOTD từ /etc/motd + script trong /etc/update-motd.d/.

06SSH hook (tùy chọn)

Trước khi shell khởi động, sshd kiểm tra:

  • ~/.ssh/rc — script riêng user (ưu tiên).
  • /etc/ssh/sshrc — system-wide (nếu user không có ~/.ssh/rc).

Ít dùng nhưng hữu ích để log, gửi Slack, setup đặc biệt trước shell.

07Khởi động Shell (login shell)

sshd fork một tiến trình bash làm login shell — báo hiệu bằng dấu -: -bash. Thứ tự đọc:

  • /etc/profile — system-wide, cho mọi user. Set PATH, PS1, umask.
  • /etc/profile.d/*.sh — package cài thêm bỏ script vào đây (bash_completion, nvm...).
  • ~/.bash_profile (hoặc ~/.bash_login, ~/.profile) — cá nhân user.
  • ~/.bashrc — KHÔNG tự chạy, nhưng thường được .bash_profile source. Chỗ đặt alias, function, prompt.

08Sẵn sàng

Bạn thấy prompt alice@server:~$ — hệ thống sẵn sàng nhận lệnh. Cả quá trình diễn ra trong vài trăm milliseconds.

💡 Khi logout: exit/Ctrl+D → ~/.bash_logout → /etc/bash.bash_logout → PAM session close → sshd đóng kết nối.
⚠️ Trường hợp đặc biệt ssh user@server "ls": Vẫn qua PAM đầy đủ, nhưng KHÔNG chạy /etc/profile, ~/.bash_profile. Chỉ đọc ~/.bashrc (thường thoát sớm nếu có [ -z "$PS1" ] && return). Đây là lý do biến môi trường "biến mất" khi chạy remote command.

SSH Hooks

FileVai trò
/etc/ssh/sshrcScript system-wide, chạy trước shell
~/.ssh/rcScript per-user (nếu có, sshrc bị bỏ qua)
~/.ssh/authorized_keysPublic key + option command=

Shell startup — Bash

Interactive login shell:
  1. /etc/profile
  2. /etc/profile.d/*.sh
  3. ~/.bash_profile → ~/.bash_login → ~/.profile
  4. ~/.bashrc (nếu được source)
  5. Logout: ~/.bash_logout

Non-interactive (ssh user@host command):
  - Chỉ đọc ~/.bashrc
  - KHÔNG chạy /etc/profile, ~/.bash_profile

Shell startup — Zsh

/etc/zshenv   → ~/.zshenv
/etc/zprofile → ~/.zprofile
/etc/zshrc    → ~/.zshrc
/etc/zlogin   → ~/.zlogin
Logout: ~/.zlogout → /etc/zlogout

4. Giải thích các thuật ngữ

PAM (Pluggable Authentication Modules)

Hệ thống xác thực module hóa của Linux. Thay vì mỗi app tự viết code xác thực, chúng gọi PAM. PAM đọc config (vd /etc/pam.d/sshd) rồi lần lượt gọi module .so.

SSHD (SSH Daemon)

Tiến trình nền lắng nghe cổng 22, nhận kết nối SSH. Không tự xác thực — ủy quyền cho PAM (nếu UsePAM yes) hoặc dùng public key nội tại.

4 nhóm PAM

auth: xác thực user. account: check tài khoản hợp lệ. session: chuẩn bị/dọn dẹp session. password: đổi mật khẩu.

Login vs Non-login shell

Login: shell đầu tiên khi user "đăng nhập" (SSH, tty). Đọc /etc/profile. Nhận diện bằng dấu - đầu argv[0]. Non-login: mở terminal mới sau login, chỉ đọc ~/.bashrc.

Interactive vs Non-interactive

Interactive: có prompt, chờ user gõ. Non-interactive: chạy script/lệnh rồi thoát. SSH login = interactive login shell.

MOTD (Message Of The Day)

Banner in khi login thành công. Lấy từ /etc/motd (tĩnh) + /run/motd.dynamic (động, sinh từ /etc/update-motd.d/).

Banner (issue.net)

Chuỗi hiện trước khi nhập password. Dùng cảnh báo pháp lý. Cấu hình bằng Banner /etc/issue.net trong sshd_config.

ForceCommand

Option trong sshd_config hoặc authorized_keys. Ép user chạy 1 command duy nhất thay vì shell tự do — dùng cho tài khoản backup, git-only, rsync-only.

ulimit / limits.conf

Giới hạn tài nguyên per-process: số file mở, số process, RAM, kích thước file. pam_limits.so đọc /etc/security/limits.conf và áp khi login.

/etc/environment vs /etc/profile

/etc/environment: file KEY=VALUE, PAM đọc, không có logic. /etc/profile: script bash, chỉ chạy cho login shell.

File .so

Shared Object — thư viện chia sẻ Linux (tương đương .dll Windows). PAM module ở /lib/x86_64-linux-gnu/security/ hoặc /usr/lib64/security/.

5. Debug & Troubleshoot

ssh -v user@host              # Verbose SSH client
bash -x -l                    # Trace login shell startup
strace -f -e openat ssh ...   # Trace mọi file bị mở
journalctl -u ssh             # Log sshd
tail -f /var/log/auth.log     # Debian/Ubuntu
tail -f /var/log/secure       # RHEL/CentOS
Tips: Nếu SSH login thành công nhưng biến môi trường không đúng, kiểm tra thứ tự file được đọc bằng bash -x -l. Nếu bị chặn login, xem /etc/nologin và /var/log/auth.log.
